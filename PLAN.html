내 조건으로 찾는 행복주택, zipzom

나이·혼인·소득·무주택·거주지를 한 번 등록하면 LH·SH 행복주택 모집공고 중 자격에 맞는 것만 골라 알려주고 지도에 찍어 주는 서비스. 이 문서는 데이터 소스 조사, 키 발급 절차, 매칭 규칙, Postgres 스키마, 모노레포 뼈대를 한 곳에 모은 기획 노트다.

01

개요

조건 등록

생년월일, 혼인 여부·혼인일, 자녀, 가구원수·세대 월소득, 맞벌이, 무주택, 자산·자동차, 거주지·관심 지역.

공고 수집

마이홈포털 API를 1차 소스로 LH·SH·지방공사 공고를 매일 동기화. LH API·SH RSS로 보강.

자격 매칭 · 알림

행복주택 계층별 규칙(청년·신혼부부·고령자…)으로 1차 필터. 새 공고가 조건에 맞으면 알림.

지도

카카오맵에 공고별 단지 마커. 주소는 카카오 로컬 API로 좌표화 후 DB 캐시.

가입 · 조건 입력프로필 1회 저장, 이후 수정
동기화 배치공고·단지 upsert, 신규만 지오코딩
매칭 계산프로필 × 공고 → matches
알림 · 목록새 매칭 푸시, 마감순 목록
지도 · 상세마커 클릭 → 원문 공고 링크
범위 결정. 매칭은 "지원 가능성 1차 필터"다. 공고마다 우선공급·지역 거주 요건·소득 산정 세대 범위가 달라 최종 판단은 원문 공고문으로 넘긴다. 공고문 PDF는 규칙 파서 대신 LLM(gpt-5.6-luna)으로 단지 표만 뽑고, 어드민 검수를 거쳐야 반영한다 — 환각·숫자 오독은 사람이 마지막에 잡는다.
02

아키텍처

왜 마이홈포털을 1차 소스로

LH·SH·GH 등 전 기관 공공임대 공고를 한 API로 집계하고, 단지명·주소·PNU·세대수·최소 보증금/월임대료·모집 시작/종료일까지 내려준다. 기관별 API를 각각 붙이는 것보다 스키마가 하나로 정리된다.

SH는 RSS가 유일한 소스

실측 결과 마이홈 API 319행 중 SH(서울주택도시공사) 공고는 0건. SH 행복주택은 RSS(EUC-KR, 제목 필터)로만 들어오고 단지·주소가 없어 "서울 전체"로 취급한다. LH API는 마이홈이 LH를 전부 커버해 보강용으로 남겨 둔다. 모두 notices(source, source_id)로 같은 테이블.

04

API 키 발급

공공데이터포털 (data.go.kr) — 인증키 1개

  1. 회원가입 후 로그인.
  2. 아래 4개 API 페이지에서 각각 활용신청. 개발계정은 자동승인, 활성화까지 1~2시간.
    마이홈 공공주택 모집공고 (15108420) · 마이홈 공공임대 단지정보 (15110581) · LH 분양임대공고문 (15058530) · LH 공고별 상세 (15057999)
  3. 마이페이지 › 오픈API › 인증키에서 키 복사. 계정당 인증키 1개가 승인된 모든 API에 공통.
  4. Encoding/Decoding 두 키가 보이면 Decoding(원문) 키를 DATA_GO_KR_SERVICE_KEY에 넣고 요청 시 URL 인코딩.
  5. 각 페이지 "참고문서"의 요청 파라미터 코드표 다운로드 → regions 시드.
  6. 운영 전환 시 활용사례 등록 후 운영계정 신청(트래픽 증설).

카카오 디벨로퍼스 — JavaScript 키 + REST API 키

  1. developers.kakao.com 카카오계정 로그인 › 내 애플리케이션 › 애플리케이션 추가.
  2. 앱 설정 › 플랫폼 › Web에 http://localhost:5173 및 배포 도메인 등록.
  3. 제품 설정 › 카카오맵 › 활성화. 2026-07-21 정책부터 필수. 계정당 첫 번째 활성화 앱만 무료 쿼터, 두 번째부턴 비즈월렛 연결.
  4. 앱 설정 › 앱 키: JavaScript 키 → apps/web/.env의 VITE_KAKAO_JS_KEY(브라우저 노출, 도메인 제한이 보호수단). REST API 키 → 루트 .env의 KAKAO_REST_API_KEY(서버 전용).
  5. 지도 SDK에 REST 키를 쓰면 실패한다. 키 종류 혼동 주의.

OPENAI_API_KEY=
OPENAI_MODEL=gpt-5.6-luna

# 프론트도 루트 .env 사용 (vite envDir, VITE_ 접두어만 브라우저 노출)
VITE_API_BASE=/api

통계청 2025년 수치 미발표로 LH·SH 2026 공고가 2025년 적용 금액을 유지 중. 연 1회 income_standards에 행 추가.

판정 의사코드

age  = 만나이(birth_date, today)
base = income_standards[year][min(household_size, 6)]
pct  = dual_income && rule.dual_income_pct ? rule.dual_income_pct : rule.income_pct
pct += household_size == 1 ? rule.bonus_pct_1p
     : household_size == 2 ? rule.bonus_pct_2p : 0

eligible(rule) =
     is_homeless
  && (rule.min_age  == null || age >= rule.min_age)
  && (rule.max_age  == null || age <= rule.max_age)
  && (!rule.requires_unmarried || marital_status == 'SINGLE')
  && (rule.marriage_within_years == null
        || married_at >= today - 7y
        || youngest_child_age <= rule.child_max_age)
  && (rule.income_pct  == null || household_monthly_income <= base * pct / 100)
  && (rule.asset_limit == null || total_assets <= rule.asset_limit)
  && (rule.car_limit   == null || car_value    <= rule.car_limit)

match(profile, notice) =
     notice.house_type == '행복주택'
  && notice.status in ('공고중','접수중')
  && ∃ house ∈ notice_houses : house.sigungu_code ∈ preferred (or sido)
  && ∃ rule : eligible(rule)   → matched_rules[]
의도적 단순화. 대학생 계층의 "본인+부모 소득", 신혼부부 "무자녀 10년/유자녀 14년", 산업단지근로자 계층, 공고별 지역 우선공급은 규칙에 넣지 않았다. 매칭 결과 카드에 "원문 공고문 자격 확인" 링크를 항상 붙인다.
